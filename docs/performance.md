# 1.1.1 大文件性能与验证

1.1.1 沿用已经完成真机验收的上传实现：最多 1 MiB 分块、4 个有界在途请求、平台 AES-CMAC、为每个写请求预留独立序列化缓冲。服务器写入上限更小时随协商缩减；不支持 multi-credit 时单块不超过 64 KiB。小文件按大小缩减窗口和缓冲。

## 实测条件

2026-10-11 至 2026-10-12（Asia/Shanghai），vivo V2502DA / Android 16，充电、进度页前台、屏幕亮起；Mac 通过 1000baseT 全双工网口接入局域网，文件写入内置 APFS。测试路径为文件管理器 → 系统分享 → SMB 分享。

当前连接协商为 SMB 3.0.2，服务器要求签名，未启用传输加密。优化保留了签名，没有通过关闭安全校验提速。

下表来自诊断构建上传函数的单调计时，包含连接、认证、写入、改名和资源关闭；各次成功样本均校验接收长度和 SHA-256。不是对其他设备、文件来源或网络的速度承诺。数据摘要见 [performance-data.json](performance-data.json)。

| 方案 | 文件 | 各次耗时 |
| --- | --- | --- |
| 原版 128 KiB 串行 | 256 MiB | 25.41 / 25.35 秒 |
| 512 KiB 串行 | 256 MiB | 10.83 / 11.06 秒 |
| 1 MiB 串行 | 256 MiB | 8.12 / 7.73 秒 |
| 1 MiB、系统签名、串行 | 256 MiB | 5.70 / 7.06 秒 |
| 1 MiB、系统签名、2 路 | 256 MiB | 3.27 / 3.25 秒 |
| 1 MiB、系统签名、4 路、预留缓冲 | 256 MiB | 2.81 / 3.20 秒 |
| 同配置持续 4 路 | 1 GiB | 9.66 / 9.49 秒 |
| 同配置持续 2 路 | 1 GiB | 12.20 秒 |

256 MiB 的 2 路样本未启用预留缓冲；1 GiB 的 2 路与 4 路都启用。1 GiB 的 2 路仅有一次样本，因此选 4 路是当前环境下的工程判断，不是统计意义上或跨设备的普遍结论。

去除诊断与故障注入的候选 APK 也完成了 1 GiB 真机验收：外部轮询约 10.54 秒确认服务结束，长度与哈希一致。外部观察包含采样延迟，不应与内部计时直接相减。正式 1.1.1 只将该候选的版本元数据定版，上传源码保持一致。

## 速度与内存取舍

较大分块减少逐次等待；系统 AES-CMAC 降低签名计算开销；有界流水线让响应等待与后续发送重叠。只有平台不提供 AES-CMAC 时回退原实现，其他密码算法保持原库实现。

相同 256 MiB / 4 路下，预留独立序列化缓冲将累计 Java 分配由约 1.071 GB 降至 0.294 GB（约 72.5%）。这是累计分配，不是常驻或峰值内存；现有样本没有证明预留缓冲进一步提速。

4 MiB 只是应用数据缓冲上限，整个进程还有界面、协议库和临时对象。最终候选的 1 GiB 测试中，进程 PSS 采样峰值约 154 MiB；采样值不是内存硬上限。没有使用强制 GC 或结束进程制造低占用。

## 完整性与验证边界

- 只有写入得到完整确认后才更新已确认进度、复用缓冲；全部确认后才将 `.part` 改成最终文件名。
- 原生 CMAC 通过 RFC4493 标准向量以及与原实现的不同长度、不同分段交叉校验；序列化线格式与原库逐字节对照。
- 实际取消 1 GiB 上传，以及提交两次写请求后的注入失败，均验证服务退出、解除亮屏、没有新的完整文件或 `.part` 遗留。
- 24 项单元测试覆盖窗口、偏移、尾块、部分确认、Future 错误、读取失败、取消、超时、空文件、服务器限制、签名回退、文件名与重试记录。
- 真正断网、服务器断电、磁盘满、其他品牌设备及云文件 provider：**UNVERIFIED**。服务器无法连接时，临时文件不一定能立即清除。
- 当前没有断点续传。大文件请保持进度页前台、不要锁屏；提速不代表解决了厂商后台冻结问题。

```sh
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease
```

```sh
adb shell am instrument -w local.smbshare.test/local.smbshare.CryptoInstrumentation
```

此测试构建用于验证，不作为公开下载包。
